# Launchpad 300·30·3

Ray White Mildura's 12-week training and accountability program for new sales associates. Six modules: Database Foundations, The Doorstep Appraisal, Pipeline Rhythm, The 30-Day Trust Plan, Neighbourhood Campaigns and The Scoreboard.

Three numbers in twelve weeks: **300 geo data, 30 appraisals, 3 listings.**

Live app: https://claude.ai/artifact/P2Z9UCWbcymej8pVr1FFZi

## For Damian and Luke: how to run it

**Invite an associate (Team tab, "Invite an associate")**
1. Share the page with their email (Share button, top right).
   - On the office's Claude team plan: **Contributor**. They see their own data plus the Team pulse (totals, streaks, who logged today), unless the pulse is off in Program settings.
   - Using their own Claude account: **Editor**. Claude treats people from outside the office plan as guests, and a guest Contributor can only view. Editor also lets them read every associate's numbers and the manager notes. Prefer adding them to the office Claude plan and sharing as Contributor.
   - Never turn on "anyone with the link".
2. Copy the ready-made message from the invite card and send it. It asks them to tell you before they sign up if they have not had the office Claude invite yet, so they do not end up on a personal account by accident. On first open they enter their name, email, start date and farm area, then a short welcome explains the app.

**Managers**
- Damian (the owner) is a manager automatically.
- Anyone else shared as Editor who picks "I'm a manager" on first open sends a request. It appears at the top of Team; only Damian can approve or decline it. Approving adds their email to the Monday report list.
- Managers must be shared as **Editor**. If Damian makes someone a manager who is shared as Contributor, their page says so and asks them to get their sharing changed to Editor, then reload. Damian's person page and toast carry the same reminder.
- Damian can also make an associate a manager from their person page (Role). To undo it later, use Remove as manager in the Managers list on Team. A manager's Team pulse row is hidden while they are a manager.
- Remove as manager (Managers list on Team): they lose the Team view and the Monday report. If they have logged days they go back on the program (their status is kept, or set to active if it was left). If they never logged, their status is set to left. The confirmation says which. If the report also goes to addresses typed into Program settings that belong to no other manager, the confirmation lists them, unticked; tick any that are theirs so the report stops going there too.
- Declining a request sets them up as an associate with status left, so they get no daily emails. They see "Your manager request was declined" once. If they are actually doing the program, set them Active on their page; that also clears the decline, so it is not mentioned again if they leave later.
- A pending requester can switch to the program with "I'm actually doing the program"; the app asks them to confirm first. If they switch just before Damian taps Approve or Decline, the app checks first and changes nothing.
- Each time Damian opens Team, anyone on the manager list who is no longer a manager is taken off it, along with their Monday report email. The app remembers which address it put on the report list for each manager, so that address comes off even if their profile email changed since. When a manager changes their email on their Profile, the list is updated too: straight away if they are shared as Editor, otherwise the next time Damian opens Team.
- This is an approval step in the app, not a lock: anyone shared as Editor can still read and change the program's data directly. Only share Editor with people you trust with every associate's numbers and the manager notes.

**What an associate does each day (under a minute)**
- Today: tap + for each geo data record, appraisal and listing. Optional call-session counters and a one-line note. Numbers save as they go; "Done for today" shows the verdict and any milestone.
- Adding an appraisal offers a 30-second detail sheet (address, likely-to-list window, Cold, Warm or Hot lead, action plan) that puts it in their pipeline with the next touch date (1 to 2 months: weekly; 2 to 12 months: monthly).
- This week's three: three commitments a week, picked from the drills of their Learn week or written in their own words, ticked off as they go. The week runs Monday to Sunday, so what is agreed at the Monday meeting stays up until the next one, and every Monday of the program starts a new week, including the last. Week 1 runs to the first Sunday after the first working day, so a weekend start rolls into its first Monday and the three picked while setting up count for that week. Someone who starts Tuesday to Friday has a short first and last week (13 in all). Changing a start date does not move commitments to another week.
- Team pulse: associates with status active or graduated see it. It lists everyone with status active, with their totals, streaks and who has logged today. A streak only shows while it is still alive (logged today or on the previous working day). Notes, pipelines and quiz scores are not on it; managers and anyone shared as Editor can see those. Turn it off in Program settings.
- Progress: rings, the pace needed from here, cumulative vs the soft guide, call ratios against the program benchmarks, logging streak, week by week, pipeline, learning.
- Learn: the week's lessons, drills, scripts, templates and quiz. Every week is open from day one; the current week is marked. Letters, emails and SMS have Copy message, which copies just the message, not the title or the guidance under it.
- Practice: AI role-play against a Mildura homeowner, then a scorecard against the script's beats. Uses the associate's own Claude usage, so the first call asks their permission.

**What managers see**
- Team: every associate with status (Ahead / On track / Slipping / Behind), bars for the three targets, last log, streak, who needs attention, team totals this week, manager requests, the invite helper and a CSV download of every logged day.
- Tap a person: full progress, last seven days with notes, this week's three (while their program runs), coaching prompts for the Monday meeting, manager notes (managers and anyone shared as Editor can see these), and their settings (start date, email, targets, status, and role for Damian). A target left at the program default follows Program settings if the defaults change later; only a target set to something else is kept for that person. If their records fail to load, notes are locked with a Try again button so a save cannot wipe the notes already there.
- Program settings: default targets, weeks, working days, office name, Team pulse on or off, manager emails for the Monday report. Saving writes only what you changed, so a sheet left open does not undo a change someone else made in the meantime.

**Status**
- active: in the program, gets the daily email and the Team pulse, and is listed on it. paused: still sees Today, but no daily email and no pulse. graduated: finished, still sees the pulse but is no longer listed on it.
- left: out of the program. Today and Progress show a short note ("You're not in the Launchpad program right now") instead of the daily sheet, with no logging nags, verdicts or pulse. Learn and Scripts stay open. They keep seeing what their sharing allows until you change their sharing.

**How "on track" is judged (not rigid)**
- A soft guide curve follows the funnel: geo data front-loaded, appraisals from week 3, listings expected from week 8.
- Every day the app recalculates what is needed per working day from here to hit the target. Someone behind the guide whose recent pace would still get them there reads "On track".
- No judgement in the first three working days. Listings do not drag the status down before they are expected.

**Reminders and reports (email, from Damian's Gmail)**
- Every working day at 5:50pm Melbourne time each active associate gets one short email. Not logged: a nudge. Logged and on track: congratulations with their numbers. Logged and behind: the pace from here plus one practical tip.
- Monday 7:47am: managers get the weekly team report (totals vs targets, this week, days logged, last week's three and who needs a new three, learning, pipeline, coaching prompts per person).
- Recipients come from each person's profile email and the manager list in Program settings. Anyone without an email is skipped and named in the task's summary.
- Both are scheduled tasks on Damian's Claude account ("Launchpad daily check-in emails" and "Launchpad Monday team report"). They run inside a dedicated Claude Code session titled "Launchpad mailer", which holds the Gmail connection. Pausing or deleting the scheduled tasks stops the emails; archiving that session would too.

**If something looks wrong**
- An associate sees "This page is view-only for you": they were shared as Viewer or Commenter, or as a guest Contributor. Share them as Contributor (office plan) or Editor (own account, with the warning above).
- Someone you made a manager sees "One more step": they are shared as Contributor. Change their sharing to Editor and have them reload.
- Luke cannot see the Team tab: share with him as Editor, have him pick "I'm a manager", then approve the request on Team.
- Someone started on the wrong date: open their page in Team and change the start date; every pace number recalculates, and This week's three stays with its week.
- The daily email did not arrive: check the person's email on their profile, then the scheduled task's last run in claude.ai.

**Definitions**
- Geo data: one new contact record from the farm area (owner name, phone or email, address) added to the CRM. Capture settlement date and email where possible.
- Appraisal: a kerbside or quick walk-through, with an action plan and a pipeline category.
- Listing: signed and live.

## Repo layout

- `app/index.html` page shell and styles (published as the artifact page)
- `app/app.js` the app (vanilla JS, no framework)
- `app/pace.js` pacing engine (pure functions, also runs in node)
- `app/content.js` generated bundle of all content (do not edit; run `build-content.sh`)
- `content/*.js` the content modules: `week-1.js` to `week-12.js`, `scripts.js`, `templates.js`, `roleplays.js`
- `CONTENT_SPEC.md` the schema and writing rules for content modules
- `build-content.sh` concatenates `content/` into `app/content.js`
- `test/mock-claude.js` in-browser mock of the claude.ai artifact runtime (db, user, sample, downloads)
- `test/smoke.js` Playwright end-to-end run of the associate and manager flows with screenshots

## Data (claude.ai artifact database)

- `config/program`: targets, weeks, workDays, officeName, managerIds, managerEmails, managerEmailById (the report address recorded for each manager), teamBoard, nudgeHour, timezone
- `people/<userId>`: name, email, role (associate | manager | manager-pending), startDate, farm, status (active | paused | graduated | left), targets (optional override: a number for each target set differently from the program default, null for the others; null or missing means all three follow Program settings), lastLogDate, welcomed, declinedAt (set when a manager request is declined), focus (this week's three, summarised: week, monday, total, done, items; see weeks below), summary (a snapshot the app writes each time a day is saved, so every value is as of summary.asOf: asOf, totals, bands, overall, needPerDay, streak, week (the program week), focusWeek (the This week's three week on asOf), dayIndex, totalDays, remainingDays, loggedDays, missedDays, targets, thisWeek, ratios, programStatus).
- `people/<userId>/days/<YYYY-MM-DD>`: geo, appraisals, listings, calls, connections, appointments, sessions, note, closed, updatedAt
- `people/<userId>/pipeline/<id>`: address, kind, category (1-2 | 2-12), group (cold | warm | hot), plan, date, lastTouch, nextTouch, reappraisal, status (active | listed | lost), notes
- `people/<userId>/learning/progress`: lessonsRead, drillsDone, quiz, practice
- `people/<userId>/weeks/<YYYY-MM-DD>`: This week's three, stored under the date of that week's Monday: week, monday, items [{ text, done, doneAt }], updatedAt. Weeks count from the Monday of the first working day to the Monday of the last working day, so each Monday in between starts the next week. Before the first working day the first week applies; after the last one, the last week. A start date change does not move these documents.
- `board/<userId>`: name, week, totals, targets, streak (as of the last save), lastLogDate, status (active | paused | graduated | left | manager; the pulse shows active rows only). The Team pulse; nothing private
- `coaching/<userId>`: manager notes (editors and the owner only)

**Reading the data (the daily email and the Monday report).** "Today" is the Melbourne date; S is startDate, weeks and workDays come from config/program.
- summary is not refreshed for someone who stops logging. Work out the program week, the day and the total working days from S and today, not from summary. This prints week, day, total and the previous working day: `python3 -c "import datetime as t,sys,json;S,D=(t.date.fromisoformat(x) for x in sys.argv[1:3]);N=int(sys.argv[3]);W=json.loads(sys.argv[4]);E=S+t.timedelta(days=7*N-1);wd=lambda x:x.isoweekday()%7 in W;n=lambda b:sum(1 for i in range((min(b,E)-S).days+1) if wd(S+t.timedelta(i)));print(0 if D<S else min(N+1,(D-S).days//7+1),n(D),n(E),next(D-t.timedelta(i) for i in range(1,8) if wd(D-t.timedelta(i))))" S D weeks '[1,2,3,4,5]'`
- Use summary.streak only when lastLogDate is on or after the previous working day; otherwise the streak is 0 (the Team pulse rule). When lastLogDate is earlier than that, say "no log since <lastLogDate>" and give overall and needPerDay as "as of <summary.asOf>", or leave them out; never report them as current. The Monday report lists these people first.
- This week's three: the focus Monday for a date D is the Monday on or before D, kept between the Monday of the first working day and the Monday of the last one. This prints the focus week number and that Monday: `python3 -c "import datetime as t,sys,json;S,D=(t.date.fromisoformat(x) for x in sys.argv[1:3]);E=S+t.timedelta(days=7*int(sys.argv[3])-1);W=json.loads(sys.argv[4]);w=[S+t.timedelta(i) for i in range((E-S).days+1) if (S+t.timedelta(i)).isoweekday()%7 in W] or [S,E];m=lambda x:x-t.timedelta(days=x.weekday());k=min(max(m(D),m(w[0])),m(w[-1]));print((k-m(w[0])).days//7+1,k)" S D weeks '[1,2,3,4,5]'`. Focus is current only when focus.monday equals today's focus Monday. Last week's three are in weeks/<focus Monday for yesterday>; the person needs a new three when today's focus Monday is later. Never use summary.week or summary.focusWeek for this.

Access rules: config readable by everyone, writable by editors; each person reads and writes their own `people/<userId>` record and everything under it, and editors read and write everyone's; board readable by Contributors and up, each person writes only their own row and editors write any row; coaching readable and writable by editors only. Anyone shared as Editor holds the editor level, so they can read every associate's records and the manager notes.

## Updating the app

Edit the files, run `./build-content.sh` if content changed, run `cd test && node smoke.js all` (needs Playwright with Chromium), then republish the artifact at the same URL with `index.html` as the page and `app.js`, `pace.js`, `content.js` as its files.
